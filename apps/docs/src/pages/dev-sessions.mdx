# Dev Sessions

A **dev session** is a named, persistent directory that your dev script can write state into across restarts. Each session gets a random slug name (e.g. `happy-walrus`) and lives at `<dir>/.data/sessions/<slug>/`.

## Session lifecycle

When your script starts, `devsess` calls `getLatestOrCreate` — it returns the most recently active session if one exists, otherwise creates a new one. You typically never manage sessions manually; `defineDevCli` handles this.

```ts
// Inside run():
const session = yield* ctx.session
console.log(session.name)          // e.g. 'happy-walrus'
console.log(yield* session.path('pglite'))  // '<dir>/.data/sessions/happy-walrus/pglite'
```

`ctx.session` is an `Effect` that resolves the current `DevSession`. A `DevSession` has:

- `session.name` — the slug string
- `session.path(rel)` — an `Effect<string>` that resolves the absolute path to a subdirectory inside the session (creating it if needed)

## Sticky port

Each session remembers a port number. The first time `getStickyPort()` is called for a session, it finds a free port and writes it to the session directory. Subsequent calls return the same port.

```ts
const port = yield* ctx.getStickyPort()
// port is stable across restarts for this session
```

This means your dev server always binds to the same port within a session — useful for browser tabs, OAuth callbacks, and tool configs that depend on a fixed URL.

## Managed subprocesses

`ctx.runManagedSubprocess(cmd, args, options?)` starts a child process that is automatically killed when the Effect scope closes (i.e. when your script exits or is interrupted).

```ts
yield* ctx.runManagedSubprocess('bunx', ['vite'], {
	env: { PORT: '3000' },
})
```

Options:

| Field | Type | Description |
|-------|------|-------------|
| `env` | `Record<string, string>` | Extra environment variables merged with `process.env` |

## Running signals

Services can signal to each other that they are ready using `publishRunning` and `awaitRunning`. This is useful when one subprocess must wait for another (e.g. a dev database) to be healthy before starting.

```ts
// In the service that becomes ready:
yield* ctx.publishRunning({ port: 5432 })

// In a dependent service:
const data = yield* ctx.awaitRunning('my-db-pkg')
```

`publishRunning(data)` writes a JSON file to the session directory. `awaitRunning(pkg)` polls until that file appears, then returns its contents.

## SessionState

`SessionState.slot(schema)` creates a typed key-value store backed by a JSON file inside the session directory. Use it to persist arbitrary structured state across restarts.

```ts
import { SessionState } from 'devsess'
import { Schema } from 'effect'

const MyState = SessionState.slot(Schema.Struct({
	lastPort: Schema.Number,
}))

// Read (returns Option):
const existing = yield* MyState.read(session)

// Write:
yield* MyState.write(session, { lastPort: 3001 })
```

## Low-level: DevSessions layer

If you need direct access to the session store outside of `defineDevCli`, you can use the `DevSessions` service and `makeDevSessionsLayer`:

```ts
import { DevSessions, makeDevSessionsLayer } from 'devsess'
import { Effect, Layer } from 'effect'

const program = Effect.gen(function* () {
	const sessions = yield* DevSessions
	const session = yield* sessions.getLatestOrCreate()
	// ...
})

program.pipe(
	Effect.provide(makeDevSessionsLayer('/path/to/project')),
	Effect.runPromise,
)
```
